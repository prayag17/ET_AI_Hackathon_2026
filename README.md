# 🌫️ Ahmedabad AQI Forecasting & Advisory System

> **ET AI Hackathon 2026** — A 1km-resolution air quality forecasting system for Ahmedabad that combines LightGBM ML predictions with official GRAP-style civic response advisories.

The system predicts AQI for each of 502 grid cells across Ahmedabad at 24h, 48h, and 72h horizons, serves the predictions via a FastAPI backend, and visualises them on an interactive heatmap with a time-slider and advisory panel.

## 🧠 1. Training the Model

The ML pipeline uses **LightGBM** to forecast AQI at 24h, 48h, and 72h horizons for each of the 502 grid cells.

### Full Training Pipeline (from raw data)

```bash
cd ai_model
```

#### Step 1 — Build Feature Store
```bash
python build_feature_store.py
```
Merges `city_hour.csv` (Kaggle hourly AQI), weather data, traffic patterns, and IDW-interpolated spatial readings across all 502 grid cells.

**Input:** `data/city_hour.csv`, `data/sensor_locations.csv`, `data/features/weather_history.csv`
**Output:** `data/feature_store.csv` (64 MB, ~500K+ rows)

#### Step 2 — Add Baselines
```bash
python baseline.py
```
Generates persistence (same AQI as N hours ago) and seasonal (same hour last week) baseline predictions for comparison.

**Input:** `data/feature_store.csv`
**Output:** `data/with_baselines.csv`

#### Step 3 — Train LightGBM Models
```bash
python train.py
```
Trains three LightGBM regressors (24h, 48h, 72h) with hyperparameter tuning across 4 configurations. Uses a time-respecting 80/20 train/test split.

**Input:** `data/features_ready.csv`
**Output:**
- `models/model_24h.pkl`, `models/model_48h.pkl`, `models/model_72h.pkl`
- `data/model_predictions.csv` (test-set predictions)
- `reports/tuning_log.csv` (hyperparameter search results)

#### Step 4 — Evaluate (Scorecard)
```bash
python scorecard.py
```
Computes RMSE, MAE, and skill scores for each horizon. Confirms the model beats both baselines.

**Input:** `data/with_baselines.csv`, `data/model_predictions.csv`
**Output:** Printed scorecard to terminal

### Feature Columns Used

The model uses 21 features (see `FEATURE_COLUMNS` in `ai_model/train.py`):
- **Weather:** `wind_speed`, `temp`, `humidity`
- **Traffic:** `traffic_index`
- **Temporal:** `hour`, `dow`, `hour_sin`, `hour_cos`, `dow_sin`, `dow_cos`, `month`
- **Calendar:** `is_public_holiday`, `is_weekend`, `is_crop_burning_season`, `is_diwali_window`
- **Lag features:** `aqi_lag_3h`, `aqi_lag_6h`, `aqi_lag_24h`
- **Rolling stats:** `aqi_roll_mean_24h`, `aqi_roll_std_24h`, `aqi_trend_6h`

## 🚀 3. Running the App

### Quick Start (two terminals)

**Terminal 1 — Backend:**
```bash
cd backend
uv run fastapi dev main.py
```
> Server starts at `http://127.0.0.1:8000`
> On Windows, if you see emoji-related crashes, prefix with: `$env:PYTHONIOENCODING='utf-8'`

**Terminal 2 — Frontend:**
```bash
cd frontend
pnpm dev
```
> Opens at `http://localhost:3000`

### API Endpoints

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/maps/getMap` | GET | GeoJSON 1 km grid (502 cells, centroids + row/col) |
| `/maps/getBoundary` | GET | Ahmedabad city boundary GeoJSON |
| `/maps/getPollution` | GET | Current T=0 AQI snapshot per cell |
| `/maps/getForecast` | GET | 73 hourly snapshots (T+0 … T+72) |
| `/maps/getAdvisory` | GET | GRAP action plan recommendations |
| `/maps/ws` | WebSocket | Live-update channel — broadcasts `{"type": "data_updated"}` when the pollution data changes on disk |

### Live auto-updates

The backend keeps the data fresh end to end, no manual pipeline runs needed:

1. **Hourly refresh** — a lifespan task re-runs `live_inference.py` every
   hour (Open-Meteo data is hourly), rewriting
   `ai_model/data/grid_pollution_demo.csv` and `backend/forecast_demo.json`
   with the latest readings + LightGBM forecasts. On startup it only runs if
   the current snapshot is older than an hour, so dev-server reloads don't
   hammer the API; a failed run keeps the previous snapshot and retries in
   10 minutes. Tune with the `LIVE_REFRESH_SECONDS` env var (`0` disables).
2. **Push to dashboards** — a watcher notices the rewritten CSV and
   broadcasts over `/maps/ws`; the frontend's `useLiveUpdates()` hook then
   refetches the pollution, forecast, and advisory queries in place — no
   reload. The sidebar header shows a **Live / Offline** dot with the real
   connection state.

The same broadcast fires if a teammate runs `live_inference.py` or
`interpolation.py` by hand — the watcher only cares that the file changed.

### Environment Variables (optional)

| Variable | Required | Description |
|----------|----------|-------------|
| `OPENROUTER_API_KEY` | No | API key for OpenRouter (Gemma 4 LLM). If not set, the advisory endpoint falls back to a deterministic rule-based system using `grap.py` directly. |

## 🔄 Updating the Demo Data

The interpolation script has a configuration flag to toggle between real-time and severe-pollution demo data:

```python
# In ai_model/interpolation.py, line ~170
USE_SEVERE_DEMO_DATE = False   # Use latest real AQI (low/moderate)
USE_SEVERE_DEMO_DATE = True    # Force historical severe winter date (400+ AQI zones)
```

**For real time data, use**
```bash
cd ai_model
python live_inference.py
```

**To refresh the demo after changing the flag:**
```bash
cd ai_model
python interpolation.py          # Regenerates grid_pollution_demo.csv
cd ..
python extract_forecast.py       # Syncs forecast_demo.json with the new date
```

The backend will serve the updated data on next request (hot-reload if running in dev mode).

## 🏗️ GRAP Advisory System

The advisory pipeline maps forecasted AQI to the **Graded Response Action Plan (GRAP)** — a staged civic response framework based on CAQM's official thresholds:

| Stage | AQI Range | Category | Example Actions |
|-------|-----------|----------|-----------------|
| No Stage | 0–200 | Good / Moderate | Routine monitoring only |
| Stage I | 201–300 | Poor | Dust control, PUC enforcement, road sweeping |
| Stage II | 301–400 | Very Poor | DG set restrictions, parking fee hikes |
| Stage III | 401–450 | Severe | Halt C&D activity, vehicle restrictions, hybrid schooling |
| Stage IV | 451+ | Severe+ | Truck entry bans, emergency odd-even, college closures |

The LLM advisor (`advisor.py`) uses the Gemma 4 model via OpenRouter to generate natural-language recommendations, with a fully deterministic fallback when the API is unavailable.
